# vfunc.js

> vfunc.js는 빌드가 필요 없는 순수 Vanilla JavaScript UI 라이브러리입니다(Apache-2.0). Virtual DOM 없이 innerHTML로 렌더링하고, 이벤트는 위임으로, 요소는 `data-ref`로 찾습니다. 기본 개념: HTML은 그대로 쓰고 제어가 필요한 곳만 vfunc로 만든다. 전역은 `vf` 하나입니다.

vfunc.js 1.0(릴리스 후보)용입니다. 전체 레퍼런스는 llms-full.txt(이 파일의 영어판 + 사이트 가이드·API 레퍼런스 + 타입 선언)이고, 이 파일에는 올바른 코드를 쓰는 데 필요한 것만 담았습니다. 코드 예시와 API 설명은 영어판 llms.txt와 같습니다.

## 불러오기

- 스크립트 태그: `<script src="https://cdn.jsdelivr.net/npm/vfunc@1.0.0-rc.5/dist/vfunc.min.js" integrity="sha384-XVwq6bBMZad0alIKEG7vuAoxb0oNsyXYdIX6MxQGyF/NYfvVQjhzD8gJIStaZ2a/" crossorigin="anonymous"></script>` → 전역 `vf`. 운영에서는 정확한 버전과 SRI를 붙입니다. integrity 값은 버전·파일마다 다릅니다(이 값은 1.0.0-rc.5의 vfunc.min.js). `dist/vfunc.js`는 경고가 나오는 개발용입니다.
- ES 모듈: `import vf from 'vfunc'` 또는 `import { vfunc, html, router } from 'vfunc'`. 복사한 파일도 같습니다(`import vf from './lib/vfunc.esm.min.js'`). ES 모듈은 `window.vf`를 건드리지 않습니다.
- IE11·Edge IE 모드: `dist/vfunc.legacy.min.js`(API 동일, Promise 폴리필만 포함). 앱 코드도 ES5여야 합니다. 화살표 함수·const/let·템플릿 리터럴·클래스를 쓰지 말고, vf.html 템플릿 리터럴 대신 `vf.tpl('<b>{name}</b>', data)`을 씁니다. 앱에 필요한 다른 기능(Object.assign, fetch 등)은 앱이 직접 폴리필합니다. 불러오기: `<script type="module" src="app.js">` + `<script nomodule src="vfunc.legacy.min.js">` + `<script nomodule src="app.es5.js">`.

## 코드 생성 규칙

1. 동적 마크업은 모두 `vf.html`(태그 템플릿)이나 `vf.tpl`로 만듭니다. 사용자 데이터를 HTML 문자열에 이어 붙이지 않습니다. `vf.unsafeHtml`은 직접 작성한 마크업에만, 왜 안전한지 주석과 함께 씁니다.
2. 이벤트는 `data-action` 셀렉터의 `delegates`나 id의 `events`로 겁니다. CSS 클래스로 고르지 않고, `onclick="…"`을 쓰지 않습니다.
3. 요소는 `data-ref`(`inst.refs.name`)나 `id`(`inst.ids.id`)로 찾습니다.
4. 디자인은 JS에 넣지 않습니다. 스크립트에 색·글꼴·간격을 쓰지 않고, CSS는 `var(--vf-*)` 토큰을 씁니다.
5. `vf.*` 멤버와 네이티브 prototype을 고치지 않습니다. 확장은 `vf.use`로 `vf.ext`에 둡니다.
6. 클라이언트 라우트는 접근 제어가 아닙니다. 권한은 서버에서 검사합니다. 토큰은 store에 두지 말고 HttpOnly 쿠키를 권장합니다.
7. `eval`, `new Function`, 문자열 `setTimeout` 금지.

## vf.vfunc(options) — 컴포넌트 (`new` 있어도 없어도 됨)

옵션: `tag`('div'), `opts`(루트 속성. innerHTML/outerHTML/srcdoc와 문자열 on*은 거부), `innerHTML`(신뢰하는 초기 마크업), `render(state)` → vf.html 결과(`this`는 인스턴스), `replaceRoot`(기본 false: 루트는 `tag` 요소 — vf.attach는 대상 요소 자체 — 이고 마크업은 그 안쪽, true: 마크업의 첫 요소가 루트), `state`, `methods`, `events: [{ id?, eventType, onEvent? }]`(`id`는 루트 안 요소의 id. 없으면 루트 자체에 걸림), `delegates: [{ selector, eventType, onEvent? }]`, `childs: [인스턴스 | 노드 | { targetId, component }]`, `onEvent`, `onError`, `onMount`, `onUpdate`, `onDestroy`.

이벤트 객체 `e`: `sender`(인스턴스), `event`, `eventType`, `target`(붙은 요소 또는 일치한 요소), `id`, `data`.

인스턴스: `$node`, `state`, `methods`, `ids`, `refs`, `setState(patch)`(한 tick에 한 번 렌더), `scheduleRefresh()`, `refresh()`, `mount(부모 또는 선택자)` → Promise, `destroy()`, `toString()`(outerHTML). 바로 접근: `inst.count` ↔ `inst.state.count`(대입하면 렌더 예약), `inst.save()` → methods, `inst.btnSave` → ids. 우선순위는 state > methods > ids. 예약어는 바로 접근할 수 없습니다: $node, state, methods, ids, refs, isvfunc, setState, refresh, scheduleRefresh, mount, destroy, toString, valueOf, `_`로 시작하는 이름. 인스턴스에 직접 속성을 붙이지 않습니다(`_`로 시작하는 이름은 엔진 몫). 리스너 함수와 타이머는 클로저나 모듈 변수에 둡니다.

```js
const counter = vf.vfunc({
  state: { count: 0 },
  render: (s) => vf.html`<button type="button" data-action="inc">${s.count}</button>`,
  delegates: [{ selector: '[data-action="inc"]', eventType: 'click',
                onEvent: (e) => { e.sender.count++; } }]
});
counter.mount('#app');
```

refresh: 루트 안쪽을 교체하고, `childs`는 다시 옮겨 붙이며(상태 유지), `data-vf-keep="key"` 요소는 새로 만들지 않고 옮깁니다(서드파티 위젯은 여기에 두고 `onMount`에서 만들고 `onDestroy`에서 정리). 포커스와 커서 위치를 복원합니다. `onMount`는 `mount()`와 `vf.attach()`에서만 호출되고 `childs`의 자식에는 호출되지 않습니다. 엔진은 자식을 자동으로 destroy하지 않으니 컨테이너에 위임을 모으거나 부모의 `onDestroy`에서 자식을 정리합니다.

## vf.html과 관련 함수

- `vf.html\`…\``은 위치별로 처리합니다: 텍스트(이스케이프, 배열은 이어 붙임, vf.html 결과와 인스턴스는 마크업으로, null/undefined/false → ''), 따옴표 속성(이스케이프. 배열은 공백으로 이어 붙임, null/undefined → ''. `false` → ''이지만 `aria-*`/`data-*`에서는 boolean이 `"true"`/`"false"`로 남으므로 `aria-selected="${on}"`이 맞게 동작), URL 속성 href/src/action/formaction/poster/cite…(이스케이프 + `vf.safeUrl`), 태그 안은 속성 이름만(`<button ${disabled ? 'disabled' : ''}>`), 태그 이름은 script/style/iframe/svg… 제외.
- 거부: `on*` 속성, `srcdoc`, 따옴표 없는 값(`class=${x}`), `<script>`/`<style>` 내용, 함수. 값을 빼고 알리며, `vf.config({ strict: true })`면 예외를 던집니다(개발·테스트에서 권장).
- `vf.tpl('<a href="{url}">{label}</a>', data)` — 템플릿 리터럴 없이 같은 보호(ES5).
- `vf.esc(v)` → 문자열, `vf.nl2br(v)` → SafeHtml, `vf.safeUrl(u)` → http/https/mailto/tel/상대 경로 또는 '#', `vf.unsafeHtml(markup)`.

## vf.attach(target, options) — 퍼블리싱 HTML 제어

옵션은 `vf.vfunc`와 같습니다. 기존 요소가 루트가 되고 속성과 리스너가 유지됩니다. `render`/`innerHTML`이 없으면 마크업과 입력값도 그대로입니다. `render`가 있으면 `render`는 요소의 **안쪽만** 돌려줍니다(요소 태그를 다시 적지 않음). 요소 자신의 태그 안으로 파싱하므로 `<tbody>`에는 `tag` 없이 행을 그릴 수 있습니다. 상태에 따라 바뀌는 루트 속성은 `onMount`/`onUpdate`에서 설정합니다(`inst.$node.setAttribute(…)`). `replaceRoot: true`면 마크업의 첫 요소가 요소 자체를 대체합니다. 대상이 없으면 null.

## 헬퍼

`vf.$(sel, root?)`, `vf.$$(sel, root?)` → 배열, `vf.el(tag, props?)`(opts와 같은 안전 규칙), `vf.node(html)`, `vf.frag(html)`, `vf.idMap(root)`, `vf.form.values(target, { skipPassword? })`(체크박스·라디오 → boolean, 다중 select → 배열), `vf.form.reset(target)`. 폼 값을 로그로 남기지 않습니다.

## SPA

`vf.router({ mode: 'hash' | 'history', base, routes: { '/users/:id': (ctx) => … }, notFound, onChange, linkSelector: 'a[data-link]', focus: 'main' })` → `start()`, `stop()`, `go(path, { replace? })`, `replace(path)`, `current()`, `href(path)`. `go`는 `/`로 시작하는 앱 경로만 받습니다. 링크: `<a data-link href="#/users/7">`.

`vf.store(initial)` → `get(key?)`(키가 없으면 전체 상태), `set(patch | (state) => patch)`(얕은 병합: 다른 키는 유지, 한 tick에 한 번 알림), `subscribe(fn)`(새 상태를 받음) → 해제 함수.

## 다국어

`vf.i18n.setup({ locales, fallback, messages, load, persist })`, `vf.t(key, params)`(평문, 복수형 `{ zero?, one, other }`와 `params.count`), `vf.i18n.set(locale)`, `subscribe(fn)`, `apply(root?)`(`data-i18n`, `data-i18n-attr`), `vf.fmt.number/currency/date/relative`.

## 디자인 토큰 (선택: css/vfunc.tokens.css)

토큰 이름은 공개 API입니다. 목록은 영어판 llms.txt와 같습니다(`--vf-color-primary`, `--vf-color-text-muted`, `--vf-space-3`, `--vf-chart-1..8` 등). 다크 테마는 OS를 따르고 `<html data-theme="light|dark">`로 강제합니다. 덮어쓸 때는 vfunc.tokens.css **다음에** 자기 CSS에서 선언합니다. 상태는 `aria-*`/`data-state`로 쓰고 CSS가 꾸밉니다. 라이브러리에 색이 필요할 때만 JS에서 getComputedStyle로 토큰을 읽습니다.

## update 플러그인 (dist/plugins/update.min.js → 전역 vfUpdate, ESM은 `import vfUpdate from 'vfunc/plugins/update'`)

`vf.use(vfUpdate, { url: './version.json', current: APP_VERSION, policy: 'next-navigation' | 'prompt' | 'immediate', interval: 10, onAvailable })` → `vf.ext.update`(`check`, `status`, `navigated`, `apply`, `stop`). version.json은 `{ "version": "1.0.3" }`이고 index.html과 함께 no-cache로 서빙합니다. 플러그인은 UI를 그리지 않고, 안내는 앱이 그립니다.

## 흔한 실수

- 컴포넌트는 만드는 순간 렌더합니다. vf.t를 쓰는 컴포넌트는 `vf.i18n.setup()` 이후에 만드세요.
- `childs`의 자식에는 onMount가 호출되지 않습니다. onMount가 필요하면 직접 mount하세요.
- `data-vf-keep` 요소는 예전 속성도 그대로입니다. 바뀌는 속성은 onUpdate에서 갱신하세요.
- 항목별 버튼·체크박스에 `id`를 주면 refresh 뒤에도 포커스가 복원됩니다.
- CSP가 있으면 인라인 `style="…"`과 인라인 `<script>`를 쓸 수 없습니다. 파일로 두세요(보이기/숨기기는 `hidden` 속성).
- 표의 행은 table 안에서 파싱해야 합니다. `<tbody>`/`<tr>`을 렌더하는 `vf.vfunc`는 `tag: 'table'`(또는 `'tbody'`). `<tbody>`에 붙인 `vf.attach`는 따로 줄 것이 없습니다. `vf.node`/`vf.frag`는 `<div>`에서 파싱하므로 행에는 쓰지 않습니다.
- 데이터·로케일 주소는 모듈 기준(`new URL('./data/x.json', import.meta.url)`)으로 만들어야 버전 폴더 안에서도 맞습니다.
