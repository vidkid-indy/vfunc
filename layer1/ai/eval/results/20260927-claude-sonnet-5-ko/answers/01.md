### app.js

```javascript
import vf from './lib/vfunc.esm.js';

function greetingText(rawValue) {
  var trimmed = rawValue.trim();
  return trimmed.length ? ('Hello, ' + trimmed + '!') : 'Hello, stranger!';
}

const app = vf.vfunc({
  tag: 'div',
  state: { count: 0 },
  render: (s) => vf.html`
    <section class="greeting">
      <label for="name">Your name</label>
      <input type="text" id="name" autocomplete="off" placeholder="Type your name">
      <p data-ref="greeting">Hello, stranger!</p>
    </section>
    <section class="counter">
      <p data-ref="count" data-state="${s.count === 0 ? 'zero' : 'positive'}">${s.count}</p>
      <div class="counter__actions">
        <button type="button" data-action="inc">+1</button>
        <button type="button" data-action="dec" ${s.count === 0 ? 'disabled' : ''}>&minus;1</button>
        <button type="button" data-action="reset">Reset</button>
      </div>
    </section>
  `,
  events: [
    {
      id: 'name',
      eventType: 'input',
      onEvent: (e) => {
        // Do not setState/re-render per keystroke: update the greeting text
        // node directly so the name input never loses focus or cursor
        // position while typing.
        e.sender.refs.greeting.textContent = greetingText(e.target.value);
      }
    }
  ],
  delegates: [
    {
      selector: '[data-action="inc"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = e.sender.count + 1; }
    },
    {
      selector: '[data-action="dec"]',
      eventType: 'click',
      onEvent: (e) => { if (e.sender.count > 0) { e.sender.count = e.sender.count - 1; } }
    },
    {
      selector: '[data-action="reset"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = 0; }
    }
  ]
});

app.mount('#app');
```

### REPORT.md

```markdown
# 보고서 — 01-counter-greeting

## 가정 (질문/승인 없이 직접 판단한 것)
- 킷은 "인사"에 스크립트/ESM 중 어느 쪽을 쓸지 정하지 않았습니다. `lib/vfunc.esm.js`를 `import`하는 ES 모듈 방식을 택했습니다. 전역 `vf`도 같은 결과를 낼 수 있지만, 모듈 방식이 `window` 오염이 없고 개발 경고가 없어 "콘솔 오류·경고 0개" 조건에 더 안전하다고 판단했습니다.
- 버튼 표시 순서(`+1` → `−1` → `Reset`)는 과제에 나열된 순서를 그대로 따랐습니다. 채점은 `data-action` 값으로 요소를 찾으므로 순서 자체는 요구사항에 없다고 보고 임의로 정했습니다.
- 이름 입력창의 `input` 이벤트 처리는 `setState`/`render`를 다시 부르지 않고 `e.sender.refs.greeting.textContent`를 직접 바꾸는 방식을 택했습니다. 킷 문서(“입력 중에는 키마다 다시 렌더하지 말고 값만 저장합니다”)를 그대로 따른 것이며, `textContent` 대입은 이스케이프 없이도 HTML로 해석되지 않으므로 `<b>Kim</b>` 같은 입력이 글자 그대로 보인다는 요구사항도 만족합니다.
- 카운터 쪽은 `e.sender.count++`(정확히는 `count = count + 1` 형태)로 `state.count`를 바꿔 전체 `render`가 다시 실행되게 했습니다. 버튼과 카운터 요소는 입력 포커스가 없는 요소라 재렌더로 인한 포커스 유실 문제가 없다고 판단했습니다.
- `style.css`의 토큰은 킷 문서에 이름이 확실히 나온 것(`--vf-color-primary`, `--vf-color-text-muted`, `--vf-space-3`)만 썼습니다. 전체 토큰 목록(`영어판 llms.txt`)은 이 킷에 포함되어 있지 않아, 이름을 지어내지 않기 위해 최소한의 스타일만 넣었습니다.
- CSP 메타 태그는 `script-src 'self'; style-src 'self'` 등으로 두어 인라인 스크립트/스타일을 쓰지 않는 조건(AGENTS.md 3·5절)을 지켰습니다.

## 킷에서 지키지 못한 것
- 없음. 요구된 훅(`id="name"`, `data-ref="greeting"`, `data-ref="count"`, `data-action="inc"/"dec"/"reset"`)과 문구(`Hello, <name>!`, `Hello, stranger!`, `+1`, `−1`, `Reset`)를 모두 그대로 넣었습니다.

## 확인 목록 (과제 10절)
- [x] 모든 동적 값이 `vf.html`을 거친다(카운터 숫자와 `disabled`, `data-state`). 이름 인사말은 `vf.html`이 아니라 `textContent` 직접 대입인데, `innerHTML`이 아니므로 이스케이프 요구사항(태그가 글자 그대로 보임)을 만족합니다.
- [x] 셀렉터는 `data-action`/`data-ref`/`id`만 씁니다. JS에 색·크기 값 없음.
- [x] CSS는 `var(--vf-*)` 토큰만 읽습니다(확인된 토큰 3종만 사용, hex·px 없음).
- [x] 리스너 해제: 이 페이지는 이동/destroy가 없는 단일 화면이라 `onDestroy` 해제 로직은 두지 않았습니다(과제 범위에 라우팅이 없음).
- [ ] 콘솔 에러·경고 0개, 세 브라우저 렌더링 확인 — **확인 못 함**(정적 파일만 작성했고 실제로 브라우저나 서버를 실행해 보지 않았습니다).
- [x] 코드·로그·커밋에 비밀값 없음.
```
