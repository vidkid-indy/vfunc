### app.js

```js
import vf from './lib/vfunc.esm.js';

// Greeting: purely publishing markup, no state/render needed — attach only for behavior
// and keep the existing markup/input value untouched (rule: render/innerHTML 없으면 마크업 그대로).
vf.attach(document.getElementById('greeting-widget'), {
  events: [
    {
      id: 'name',
      eventType: 'input',
      onEvent: (e) => {
        const value = e.target.value.trim();
        // Direct text update (no setState/render) so the input never loses focus/cursor.
        e.sender.refs.greeting.textContent = value ? `Hello, ${value}!` : 'Hello, stranger!';
      }
    }
  ]
});

// Counter: small state, attach with render so only the section's inside is replaced
// (the section element itself stays the root, matching vf.attach semantics).
vf.attach(document.getElementById('counter-widget'), {
  state: { count: 0 },
  render: (s) => vf.html`
    <p data-ref="count" data-state="${s.count === 0 ? 'zero' : 'positive'}">${s.count}</p>
    <button type="button" data-action="inc">+1</button>
    <button type="button" data-action="dec" ${s.count === 0 ? 'disabled' : ''}>&minus;1</button>
    <button type="button" data-action="reset">Reset</button>
  `,
  delegates: [
    {
      selector: '[data-action="inc"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = e.sender.state.count + 1; }
    },
    {
      selector: '[data-action="dec"]',
      eventType: 'click',
      onEvent: (e) => {
        if (e.sender.state.count > 0) e.sender.count = e.sender.state.count - 1;
      }
    },
    {
      selector: '[data-action="reset"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = 0; }
    }
  ]
});
```

### REPORT.md

```markdown
# 보고

## 가정
1. 인사 위젯은 `vf.attach(target, { events })`만 쓰고 `render`/`state`를 주지 않았습니다(킷 4-7절: "동작만 필요한 퍼블리싱 HTML은 render 없이 vf.attach — 마크업을 유지"). 인사말 텍스트는 `setState`/재렌더가 아니라 `e.sender.refs.greeting.textContent`를 직접 바꿔서 갱신했습니다. 이렇게 하면 입력칸 자체를 전혀 다시 그리지 않으므로 포커스·커서·글자가 확실히 유지됩니다(킷 4-4절: "입력 중에는 키마다 다시 렌더하지 말고 값만 저장").
2. 이벤트 타입은 `keyup`이 아니라 `input`을 썼습니다. "키를 누를 때마다 바뀐다"는 요구를 만족하면서 IME 조합, 붙여넣기까지 포함해 더 안정적으로 동작한다고 판단했습니다. 킷에 두 이벤트 중 무엇을 쓰라는 지시는 없어 직접 판단했습니다.
3. 카운터는 `vf.vfunc` 대신 `vf.attach(section, { state, render, delegates })`를 썼습니다. `counter-widget` 섹션 자체를 루트로 재사용하고 안쪽만 `render`가 채우게 해서 불필요한 래퍼 `<div>`가 추가로 생기지 않게 했습니다(킷: "attach 옵션은 vf.vfunc와 같다", "render는 요소의 안쪽만 돌려준다").
4. `−1` 버튼 문구는 과제에 적힌 대로 유니코드 MINUS SIGN(U+2212, `&minus;`)을 썼습니다. 일반 하이픈(`-1`)이 아닙니다.
5. `disabled` 속성은 킷의 예시(`<button ${disabled ? 'disabled' : ''}>`)와 동일한 패턴으로, 0이 아닐 때는 속성 자체가 없게(빈 문자열) 했습니다.
6. CSS는 킷 llms.ko.txt에 이름이 직접 나온 토큰(`--vf-space-3`, `--vf-color-text-muted`, `--vf-color-primary`)만 썼습니다. 그 밖의 여백·색 토큰 이름은 지어내지 않았습니다. `lib/vfunc.tokens.css`를 index.html에서 연결해 토큰이 정의되어 있다고 가정했습니다.

## 확인 목록 (프롬프트 10절 대응)
- [x] 동적 값은 `vf.html`을 거치거나(카운터), 아예 `textContent` 대입(인사, HTML 파싱 자체를 하지 않으므로 `<b>Kim</b>`도 글자 그대로 보임)만 씁니다. 데이터로 `innerHTML`을 설정한 곳 없음
- [x] 셀렉터는 `id`("name"), `data-ref`("greeting", "count"), `data-action`("inc"/"dec"/"reset")만 씁니다. JS에 색·크기 값 없음
- [x] `style.css`는 `var(--vf-*)` 토큰만 참조. hex·rgb()·px 값 없음
- [ ] 새 텍스트 메시지 키/로케일 — 이 과제는 로케일 폴더가 없는 단일 페이지라 `vf.t`/`locales/*.json`을 쓰지 않았습니다. 과제 범위에 다국어 요구가 없어 생략했습니다(킷 6-1절과 어긋나지만, 이 과제 자체에 로케일 파일이 없어 적용할 대상이 없었습니다)
- [x] 리스너·타이머·구독 없음 → `onDestroy` 해제 대상 없음 (attach된 두 위젯 모두 페이지 생명주기 동안 유지)
- [ ] 콘솔 에러·경고 0개 — **확인 못 함**(이 평가 환경에서는 브라우저를 실제로 열어 볼 수 없어 실행 확인을 하지 못했습니다)
- [x] 비밀값·토큰·개인정보 없음
```
