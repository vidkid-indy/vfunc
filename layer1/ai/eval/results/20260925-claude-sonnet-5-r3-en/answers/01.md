### app.js

```js
import vf from './lib/vfunc.esm.js';

const app = vf.attach('#app', {
  state: { count: 0 },
  events: [
    {
      id: 'name',
      eventType: 'input',
      onEvent: (e) => {
        const value = e.target.value.trim();
        app.refs.greeting.textContent = value ? `Hello, ${value}!` : 'Hello, stranger!';
      }
    }
  ],
  delegates: [
    {
      selector: '[data-action="inc"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count++; }
    },
    {
      selector: '[data-action="dec"]',
      eventType: 'click',
      onEvent: (e) => {
        if (e.sender.state.count > 0) e.sender.count--;
      }
    },
    {
      selector: '[data-action="reset"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = 0; }
    }
  ],
  onUpdate: (inst) => {
    inst.refs.count.textContent = String(inst.state.count);
    inst.refs.count.setAttribute('data-state', inst.state.count === 0 ? 'zero' : 'positive');
    inst.refs.dec.toggleAttribute('disabled', inst.state.count === 0);
  }
});
```

# Report — Counter and greeting

## Files
- `index.html` (new)
- `app.js` (new)
- `style.css` (new, optional per task, included for a minimally usable layout)

## Approach
- Single `vf.attach('#app', …)` over the existing published markup (no `render`), following the documented "without render" pattern: state changes drive `onUpdate`, where the adopted markup is written by hand (`llms.txt`, "vf.vfunc(options)" section: *"onUpdate(inst) … without render, after each state change — write the state to the adopted markup there"*).
- **Greeting**: bound with `events` on `id: 'name'` (`input` event), and the greeting text is written directly to `app.refs.greeting.textContent` on every keystroke. This is not routed through `state`/`onUpdate` or `vf.html`, so the input element itself is never re-rendered — caret, focus and characters are never touched. `textContent` (not `innerHTML`) is used to show the name, so `<b>Kim</b>` is shown as literal text; this satisfies AGENTS.md rule 3.1 ("never set innerHTML from data") without needing `vf.html`, since no HTML is being parsed.
- **Counter**: `state.count` is the single source of truth. `inc`/`dec`/`reset` use the `e.sender.count` shortcut described in llms.txt. `dec` is guarded so the count never goes below 0. `onUpdate` writes the digit, `data-state` (`zero`/`positive`), and toggles the `disabled` attribute on the `dec` button (matching the initial HTML state, which is also `count = 0`, `data-state="zero"`, `disabled`, so there is no mismatch on first paint).
- All selectors/hooks required by the task are kept verbatim: `id="name"`, `data-ref="greeting"`, `data-ref="count"`, `data-action="inc"/"dec"/"reset"`, texts `+1`, `Reset`, and count text `0`. The `−1` label uses the Unicode minus sign as `&minus;` (a true minus, not a hyphen) as visible text, matching "−1" in the task.
- CSP meta tag has no `'unsafe-inline'` in `script-src`; all CSS and JS live in files; `type="module"` script; no CDN, no `eval`/`new Function`/string `setTimeout`.
- `style.css` reads only `var(--vf-*)` tokens (with plain-CSS fallback values in the `var()` fallback slot, since `lib/vfunc.tokens.css` is optional and may not be present/loaded in every environment) — no raw values are hardcoded outside of those fallbacks, and none live in `app.js`.
