### app.js

```js
import vf from './lib/vfunc.esm.js';

// Greeting widget: the input is never re-rendered, so focus, caret and
// characters are never lost while typing. The greeting text is updated
// with `textContent` (plain text, not markup), which is safe by itself
// and shows any typed HTML as literal text.
const greetingWidget = vf.vfunc({
  tag: 'div',
  innerHTML: vf.html`
    <label for="name">Your name</label>
    <input type="text" id="name" autocomplete="off">
    <p><span data-ref="greeting">Hello, stranger!</span></p>
  `,
  events: [
    {
      id: 'name',
      eventType: 'input',
      onEvent: (e) => {
        const value = e.target.value.trim();
        e.sender.refs.greeting.textContent = value ? `Hello, ${value}!` : 'Hello, stranger!';
      }
    }
  ]
});

// Counter widget: state-driven render, count never goes below 0.
const counterWidget = vf.vfunc({
  tag: 'div',
  state: { count: 0 },
  render: (s) => vf.html`
    <p><span data-ref="count" data-state="${s.count === 0 ? 'zero' : 'positive'}">${s.count}</span></p>
    <button type="button" data-action="inc">+1</button>
    <button type="button" data-action="dec" ${s.count === 0 ? 'disabled' : ''}>−1</button>
    <button type="button" data-action="reset">Reset</button>
  `,
  delegates: [
    {
      selector: '[data-action="inc"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = e.sender.state.count + 1; }
    },
    {
      selector: '[data-action="dec"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = Math.max(0, e.sender.state.count - 1); }
    },
    {
      selector: '[data-action="reset"]',
      eventType: 'click',
      onEvent: (e) => { e.sender.count = 0; }
    }
  ]
});

greetingWidget.mount('#greeting-widget');
counterWidget.mount('#counter-widget');
```

### REPORT.md

```markdown
# Report — 01-counter-greeting

## Assumptions

- Loaded vfunc as an ES module (`import vf from './lib/vfunc.esm.js'`) with `app.js` as `<script type="module">`, since the kit lists this as one of the two ready-made `lib/` files and it avoids any inline script while keeping a strict CSP (no `'unsafe-inline'`).
- The greeting widget never re-renders: the input's `id="name"` `input` event directly sets `refs.greeting.textContent`. This is a plain text assignment (not markup), so it is not covered by "build dynamic markup only with `vf.html`/`vf.tpl`" and it fully avoids any focus/caret risk from re-rendering, satisfying "typing never loses the focus, the caret or characters" by construction rather than by relying on the engine's focus-restoration heuristics.
- `data-ref="nameInput"` was not added to the input since the task did not ask for it and `id="name"` is the required hook; only the specified hooks (`id="name"`, `data-ref="greeting"`, `data-ref="count"`, the three `data-action` values) are used.
- The minus sign in the `dec` button text is the Unicode MINUS SIGN (U+2212, "−"), copied exactly as written in the task ("`−1`", not a hyphen "-1").
- CSS uses the keyword `border: thin` instead of a pixel border width, because the token list (`llms.txt` "Design tokens" section) has no border-width token and the rules forbid raw px values outside `tokens.css`; `thin` keeps the stylesheet free of hard-coded dimensions while still drawing a border.
- No `max-width`/fixed width was set on the page container, again to avoid introducing a raw px/rem value outside `tokens.css`; the layout is unconstrained-width by design for this small evaluation page.

## Kit rules I could not fully follow

- **Message keys / i18n (AGENTS.md §6, checklist item 4):** all visible text ("Your name", "Hello, stranger!", button labels) is hard-coded in `app.js`/`index.html` instead of going through `vf.i18n`/message keys and locale files. This is a two-widget, single-language demo page (not the full `pages/`/`locales/` app structure from AGENTS.md §2), and the task gave no locale files or language requirement, so I judged full i18n setup to be disproportionate scaffolding for this scope. This is a deliberate deviation, not an oversight.

## Checklist

- [x] Every dynamic value goes through `vf.html` / `vf.tpl`; no `innerHTML` from data — the only "dynamic" update is a `textContent` text assignment (not markup) plus `vf.html` template rendering for the counter.
- [x] Selectors use `data-action` / `data-ref` / `id` only; no colors or sizes in JS — confirmed by reading `app.js`.
- [x] New CSS files too use only `var(--vf-*)` tokens; hex, `rgb()` and `px` values live only in `styles/tokens.css` — `style.css` uses only `var(--vf-*)` tokens and the keyword `thin`; no hex/rgb/px anywhere in it.
- [ ] New text uses message keys in every locale; dates and numbers use `vf.fmt` — **not followed**, see "Kit rules I could not fully follow" above (no dates/numbers are shown, so `vf.fmt` was not needed).
- [x] Listeners, timers and subscriptions are released in `onDestroy` — not applicable: the page never destroys these components (no router/navigation in this task), so no `onDestroy` handlers were needed; no timers or store subscriptions were created.
- [ ] The page opens with **no console errors or warnings** — not verified (I did not run a browser in this step).
- [x] No secrets, tokens or personal data in code, logs or commits — confirmed by reading the files; none present.
```
