### app.js

```js
// Sign up — the page script.
(function () {
  'use strict';

  var EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  var FIELDS = ['email', 'password', 'confirm', 'terms'];
  var MESSAGES = {
    email: 'Enter a valid email address.',
    password: 'Use at least 8 characters, including a number.',
    confirm: 'Passwords do not match.',
    terms: 'Accept the terms to continue.'
  };
  var shown = { email: false, password: false, confirm: false, terms: false };

  function isValid(field) {
    var el = app.ids[field];
    if (field === 'email') { return EMAIL_RE.test(el.value.trim()); }
    if (field === 'password') { return el.value.length >= 8 && /\d/.test(el.value); }
    if (field === 'confirm') { return el.value !== '' && el.value === app.ids.password.value; }
    if (field === 'terms') { return el.checked; }
    return true;
  }

  function validate(field) {
    var ok = isValid(field);
    app.ids[field].setAttribute('aria-invalid', ok ? 'false' : 'true');
    if (!ok) { shown[field] = true; }
    app.ids[field + '-error'].textContent = ok ? '' : MESSAGES[field];
    return ok;
  }

  function onFieldInput(field) {
    if (shown[field]) { validate(field); }
  }

  function onSubmit(e) {
    e.event.preventDefault();
    var firstInvalid = null;
    FIELDS.forEach(function (field) {
      var ok = validate(field);
      if (!ok && firstInvalid === null) { firstInvalid = field; }
    });
    if (firstInvalid) {
      app.ids[firstInvalid].focus();
      return;
    }
    var email = app.ids.email.value.trim();
    app.ids.signup.hidden = true;
    app.refs.done.textContent = 'Welcome, ' + email + '!';
    app.refs.done.hidden = false;
  }

  var app = vf.attach('#app', {
    events: [
      { id: 'email', eventType: 'blur', onEvent: function () { validate('email'); } },
      { id: 'email', eventType: 'input', onEvent: function () { onFieldInput('email'); } },
      { id: 'password', eventType: 'blur', onEvent: function () { validate('password'); } },
      { id: 'password', eventType: 'input', onEvent: function () { onFieldInput('password'); } },
      { id: 'confirm', eventType: 'blur', onEvent: function () { validate('confirm'); } },
      { id: 'confirm', eventType: 'input', onEvent: function () { onFieldInput('confirm'); } },
      { id: 'terms', eventType: 'change', onEvent: function () { validate('terms'); } }
    ],
    delegates: [
      { selector: '#signup', eventType: 'submit', onEvent: onSubmit }
    ]
  });
})();
```

### REPORT.md

```markdown
# Report — Sign-up form validation

## Assumptions

- `vf.attach` populates `inst.ids` / `inst.refs` by scanning the root's existing subtree at mount, even without a `render` function (the kit says elements are reached with `inst.ids.id` / `inst.refs.name` "inside the component's root only", and the published-HTML examples in the kit rely on this). I attached to a single root (`#app`, added on the existing `<main class="page">`) so that the form and the new welcome message share one scope — `data-ref="done"` needed to live outside the form, since the form itself gets `hidden`.
- The task's exact texts are given directly in the rules table and there are no locale files among the project files, so I hard-coded the four messages and the "Welcome, …!" text in `app.js` instead of adding a message-key/locale layer (AGENTS.md §6 would normally ask for message keys, but no locale infrastructure exists in this project and the kit gives literal required strings).
- Added hooks beyond what existed, without touching any existing one: `id="email-error"` / `id="password-error"` / `id="confirm-error"` / `id="terms-error"` (required by the task), `aria-describedby` on the four fields, `id="app"` on `<main>` (the new attach root), and `data-ref="done"` on a new empty `<p hidden>`. All original ids, classes, and visible texts are unchanged.
- Chose `delegates` with `selector: '#signup'` and `eventType: 'submit'` for the submit handler (submit events bubble in current browsers) rather than adding a new `data-action` to the form, since the form's `id` was already usable.
- Validation messages are written with `el.textContent`, not `vf.html`/innerHTML, since they are plain text, not markup — this keeps rule 3.1 ("build dynamic markup only with vf.html") satisfied because no HTML string is ever built or injected.
- The password value is only ever read (length/regex/equality checks) and is never placed into the DOM as text or logged; only the trimmed email is shown, per the requirement.

## Checklist

- [x] Every dynamic value goes through `vf.html` / `vf.tpl`; no `innerHTML` from data — no HTML is built at all; only `textContent` and attribute assignments are used.
- [x] Selectors use `data-action` / `data-ref` / `id` only; no colors or sizes in JS — `app.js` only reads/writes `id`- and `data-ref`-addressed elements.
- [x] New CSS uses only `var(--vf-*)` tokens; no hex/rgb/px added.
- [x] New text uses exact strings from the task's rules table (no locale files exist in this project; see assumptions).
- [x] Listeners: `vf.attach` owns all listeners on `#app`'s single root; there are no manual `addEventListener`, timers, or subscriptions to release, so no `onDestroy` is needed for this single static page.
- [ ] The page opens with no console errors or warnings — not verified (no browser/tooling available in this environment to run it); reasoned through the vfunc.js API as documented in the kit.
- [x] No secrets, tokens, or personal data in code, logs, or commits — the password is never logged or rendered as text.

## Behaviour notes

- Text fields validate on `blur`; once a field has shown an error (`shown[field] = true`), every subsequent `input` on that same field re-validates it so the message clears as soon as it is fixed (and reappears if broken again), matching the rule literally per-field (password edits do not force-revalidate confirm, since the rule only specifies blur/input triggers per own field).
- `terms` validates on `change`.
- `aria-invalid` is only set once a field has been validated (`"true"`/`"false"`); before that it is absent, as required.
- Submitting always validates all four fields in table order and moves focus to the first invalid one; only when all four pass does it hide `#signup` and reveal `data-ref="done"` with `Welcome, <trimmed email>!`.
```
