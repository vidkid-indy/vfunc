### app.js

```js
import vf from './lib/vfunc.esm.js';

const app = vf.vfunc({
  tag: 'div',
  opts: { className: 'app' },
  state: { name: '', count: 0 },
  render: (s) => {
    const trimmed = s.name.trim();
    const greetText = trimmed ? `Hello, ${trimmed}!` : 'Hello, stranger!';
    const countState = s.count === 0 ? 'zero' : 'positive';
    return vf.html`
      <section class="widget widget__greeting">
        <label for="name">Your name</label>
        <input type="text" id="name" data-ref="nameInput" value="${s.name}" autocomplete="off">
        <p data-ref="greeting" aria-live="polite">${greetText}</p>
      </section>
      <section class="widget widget__counter">
        <p data-ref="count" data-state="${countState}">${s.count}</p>
        <button type="button" data-action="inc">+1</button>
        <button type="button" data-action="dec" ${s.count === 0 ? 'disabled' : ''}>&minus;1</button>
        <button type="button" data-action="reset">Reset</button>
      </section>
    `;
  },
  events: [
    {
      id: 'name',
      eventType: 'input',
      onEvent: (e) => {
        e.sender.name = e.target.value;
      }
    }
  ],
  delegates: [
    {
      selector: '[data-action="inc"]',
      eventType: 'click',
      onEvent: (e) => {
        e.sender.count = e.sender.state.count + 1;
      }
    },
    {
      selector: '[data-action="dec"]',
      eventType: 'click',
      onEvent: (e) => {
        if (e.sender.state.count > 0) {
          e.sender.count = e.sender.state.count - 1;
        }
      }
    },
    {
      selector: '[data-action="reset"]',
      eventType: 'click',
      onEvent: (e) => {
        e.sender.count = 0;
      }
    }
  ]
});

app.mount('#app');
```

### REPORT.md

## Assumptions

- No task was given for a build/adapter or i18n; kept everything in plain `vf.vfunc` + ES modules (`./lib/vfunc.esm.js`), no router/store needed for a two-widget page.
- The greeting must update on every keystroke, so the component re-renders on every `input` event (`e.sender.name = e.target.value`, a state shortcut assignment) rather than deferring to a later commit point. Per the kit, focus/caret survive this because the input keeps the same `id="name"` across renders, and the engine restores focus/caret by matching `id`/`data-ref`/`name`.
- Used the state-shortcut form (`e.sender.count = …`, `e.sender.name = …`) instead of `setState`, since both are documented as equivalent and this keeps the delegate/event handlers short.
- Added a CSP meta tag (`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; base-uri 'none'; object-src 'none'`) and used only external files (no inline `style=`/`<script>`), following AGENTS.md §3.5 even though the task did not explicitly ask for it — this is a "must" rule in the kit and costs nothing here.
- `style.css` is optional per the task; included it, using only `var(--vf-*)` tokens (linked `lib/vfunc.tokens.css` before it), no raw color/px-as-color literals, per AGENTS.md §5 and the "Design tokens" section of llms.txt. `px` values used only for borders/rounded corners are already token-driven (`var(--vf-radius-*)`, `var(--vf-space-*)`); no hardcoded color hex/rgb anywhere in JS or CSS.
- `data-ref="nameInput"` was added to the input in addition to the required `id="name"` — purely additive, does not change the required hooks, texts, or `id`.
- The dash character in the `dec` button label is written as `&minus;1` (Unicode minus, U+2212) inside the `vf.html` template to match the task text "`−1`" exactly (it uses U+2212, not a hyphen-minus); rendered text content is `−1`.
- No i18n was used (no `locales/` requirement in the task), so visible strings ("Your name", "Hello, …", "+1", "Reset", etc.) are hardcoded in `app.js`/`index.html`, consistent with "Build a small page from scratch" with no locale files listed as required inputs.
