### app.js

```js
// Sign up — the page script.

var EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

var MESSAGES = {
  email: 'Enter a valid email address.',
  password: 'Use at least 8 characters, including a number.',
  confirm: 'Passwords do not match.',
  terms: 'Accept the terms to continue.'
};

var FIELD_ORDER = ['email', 'password', 'confirm', 'terms'];

// Tracks, per field, whether its error message is currently shown
// (so text fields revalidate on every input only after a failed blur).
var shown = { email: false, password: false, confirm: false, terms: false };

function isValid(name, inst) {
  var input = inst.ids[name];
  if (name === 'terms') return input.checked;
  if (name === 'confirm') return input.value !== '' && input.value === inst.ids.password.value;
  if (name === 'password') return input.value.length >= 8 && /\d/.test(input.value);
  return EMAIL_RE.test(input.value.trim());
}

function validateField(name, inst) {
  var input = inst.ids[name];
  var errorEl = inst.ids[name + '-error'];
  var valid = isValid(name, inst);
  input.setAttribute('aria-invalid', valid ? 'false' : 'true');
  errorEl.textContent = valid ? '' : MESSAGES[name];
  shown[name] = !valid;
  return valid;
}

var doneEls = vf.$('[data-ref="done"]');
var doneEl = doneEls[0];

vf.attach('#signup', {
  delegates: [
    { selector: '#email', eventType: 'focusout', onEvent: function (e) { validateField('email', e.sender); } },
    { selector: '#email', eventType: 'input', onEvent: function (e) { if (shown.email) validateField('email', e.sender); } },
    { selector: '#password', eventType: 'focusout', onEvent: function (e) { validateField('password', e.sender); } },
    { selector: '#password', eventType: 'input', onEvent: function (e) { if (shown.password) validateField('password', e.sender); } },
    { selector: '#confirm', eventType: 'focusout', onEvent: function (e) { validateField('confirm', e.sender); } },
    { selector: '#confirm', eventType: 'input', onEvent: function (e) { if (shown.confirm) validateField('confirm', e.sender); } },
    { selector: '#terms', eventType: 'change', onEvent: function (e) { validateField('terms', e.sender); } }
  ],
  events: [
    {
      eventType: 'submit',
      onEvent: function (e) {
        e.event.preventDefault();
        var inst = e.sender;
        var firstInvalid = null;
        FIELD_ORDER.forEach(function (name) {
          var valid = validateField(name, inst);
          if (!valid && !firstInvalid) firstInvalid = inst.ids[name];
        });
        if (firstInvalid) {
          firstInvalid.focus();
          return;
        }
        var email = inst.ids.email.value.trim();
        inst.$node.setAttribute('hidden', '');
        if (doneEl) {
          doneEl.textContent = 'Welcome, ' + email + '!';
          doneEl.removeAttribute('hidden');
        }
      }
    }
  ]
});
```

### REPORT.md

**Assumptions**

- Used `focusout` (bubbling) instead of `blur` for the delegated "loses focus" rule, since `blur` does not bubble and vfunc delegation relies on bubbling.
- The welcome element `data-ref="done"` is placed as a sibling of the form inside `<main>` (not inside `form#signup`), because the task says the form itself is hidden and a separate element shows the welcome text. Since it sits outside the `#signup` root, it's looked up once via `vf.$('[data-ref="done"]')` rather than through `inst.refs`, per the kit's `vf.$(sel, root?)` helper.
- Per-field "shown" state (whether to revalidate on every `input`) is kept in a small module-level object, per AGENTS.md §4.9/§4 guidance to keep such bookkeeping in a closure/module variable rather than as custom properties on the instance.
- `#terms`'s error span is placed after its label inside the `.field--check` row and made full-width via CSS so it doesn't visually squeeze into the checkbox row; this is a structural/style choice, not a logic change, and the existing form fields, ids, and visible texts were kept unchanged.
- Submit handling is bound via `events: [{ eventType: 'submit', ... }]` (no `id`) so the listener sits on the root `<form>` itself, since a `delegates` selector targeting the root itself felt less reliable than the documented "no id → root" pattern.
- Added `aria-describedby` on `#terms` too (not just text fields) since the terms checkbox also has an associated error message element; the task only mandated it implicitly through the "each field has a message element ... and the field's aria-describedby contains that id" rule, which reads as applying to all four fields.
- `app.js` is written in ES5-style (`var`, `function`) even though the task doesn't require IE11 support, simply as a conservative, no-build-tool-dependent style; this doesn't conflict with any rule since arrow functions were also permitted (modern browsers only, per condition 4).

**Kit items I could not follow / verify**

- Nothing from the kit's `must` rules was knowingly broken.
- I could not run the app in a browser (no tool access to execute or screenshot it in this one-shot evaluation), so the checklist below reflects static review only.

**Checklist**

- [x] Every dynamic value goes through safe DOM APIs — the only dynamic content written is the welcome text, set via `textContent` (auto-escaping), not `innerHTML`/`vf.html` concatenation; no user data is placed in markup strings.
- [x] Selectors use `data-action`/`data-ref`/`id` only — delegates use `#email`, `#password`, `#confirm`, `#terms` (ids) and the welcome element uses `data-ref="done"`; no class selectors used in JS.
- [x] New text uses exact required strings (the task fixed the literal texts; no locale/message-key system exists in this single-page project, and the kit's project only requires `vf.fmt` for dates/numbers, none of which appear here).
- [x] No colors/sizes in JS — all visual styling (border color, font size) lives in `style.css` using `var(--vf-*)` tokens only.
- [x] No listeners/timers to release — `vf.attach` is called once at page load and never destroyed/navigated away from, so there is no `onDestroy` to add here (single static page, no router).
- [ ] "No console errors or warnings" — not verified (could not run the page in a browser in this evaluation).
- [x] Password never appears in the page outside its own input and never logged — `app.js` never reads or logs `inst.ids.password.value` except to compare it internally to `#confirm`'s value in memory; nothing password-related is written to the DOM, `console`, or the welcome message (only the email is shown).
- [x] `aria-invalid` is unset until first validation, then reflects `"true"`/`"false"` per field, set only inside `validateField`.
- [x] Submitting validates all four fields in table order and focuses the first invalid one; a fully valid submit hides `#signup` via the `hidden` attribute and reveals `data-ref="done"` with `Welcome, <trimmed email>!`.
